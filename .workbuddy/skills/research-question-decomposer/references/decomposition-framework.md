# 研究问题拆解框架

本文件为 `research-question-decomposer` 的判断依据，供阶段 2（规范化转述）与阶段 4（拆解与原因说明）使用。

## 目录

1. 拆解维度清单与选择规则
2. 规范化表述句式与禁忌
3. 完整示例（含确认关卡）
4. MECE 与质量自检表

## 1. 拆解维度清单与选择规则

| 维度 | 切分依据 | 适用情境 | 典型子问题形态 |
| --- | --- | --- | --- |
| 构成维度 | 按研究对象或系统的组成要素 | 系统由多个模块、主体或环节构成 | 「[要素 A] 对 [整体指标] 的贡献如何量化？」 |
| 因果维度 | 机制 → 效应 → 边界条件 | 目标是解释而非仅描述 | 「[因素] 通过什么中间机制影响 [结果]？」 |
| 尺度维度 | 时间 / 空间 / 层级 | 存在多尺度或跨层级效应 | 「[结论] 在 [尺度] 上是否仍成立？」 |
| 变量维度 | 自变量 / 因变量 / 中介 / 调节 / 控制 | 实证、实验、统计类研究 | 「[调节变量] 是否改变 [主效应] 的方向或强度？」 |
| 方法链维度 | 数据 → 表征 → 建模 → 求解 → 验证 | 方法、算法、模型、工程类研究 | 「[模型] 在 [条件] 下的收敛性与误差界是什么？」 |
| 验证维度 | 可检验假设 / 可计算量 / 可观测指标 | 需要落地评测或可证伪判据 | 「用哪些指标可以判定 [结论] 成立？」 |
| 约束维度 | 假设、边界、适用条件 | 结论泛化性存疑 | 「[假设] 放松到 [条件] 时结论是否保持？」 |

选择规则：

- 一次拆解**只选一个主维度**，其余维度至多辅助一条，避免子问题粒度混杂。
- 机制解释类问题优先「因果维度」；方法/模型类优先「方法链维度」；系统工程类优先「构成维度」；实证类优先「变量维度」。
- 若两个维度同样合理，不要自行决定，放入阶段 2 的待确认项请用户选择。
- 维度选择必须能在阶段 4 的「拆解逻辑」中说出理由。

## 2. 规范化表述句式与禁忌

| 目标 | 句式模板 |
| --- | --- |
| 因果 / 影响 | 在 [约束/场景] 下，[对象] 的 [因素] 如何影响 [指标]？其效应量如何度量？ |
| 机制解释 | [因素] 通过何种中间机制作用于 [结果]？该机制可由哪些可观测量验证？ |
| 方法性质 | [方法/模型] 在 [条件] 下的 [收敛性/稳定性/复杂度/误差界] 是什么？ |
| 量化表征 | 如何定义并量化 [抽象量]，使其满足 [性质]？ |
| 边界条件 | [结论] 在 [条件变化] 下是否成立？失效的临界条件是什么？ |
| 比较择优 | 在 [指标集] 上，[方案 A] 与 [方案 B] 的差异及各自适用条件是什么？ |

表述禁忌：

- 「研究…」「探讨…」「分析…」单独作谓语，没有可检验的出口。
- 「更好」「有效」「优化」「智能」等未定义比较基准或判据的词。
- 一句话塞入两个以上待检验命题（违反原子性）。
- 隐含未声明的数据、场景或假设前提。
- 用术语堆叠掩盖概念未定义，例如「基于深度学习的拥堵智能优化」。

## 3. 完整示例（控制 / 智能交通方向）

**用户原始输入**

> 我想做点关于信号灯配时和拥堵的研究，深度学习能不能帮上忙，感觉范围有点大。

**阶段 1 · 忠实复述**

> 我理解你提出的问题是：「我想做点关于信号灯配时和拥堵的研究，深度学习能不能帮上忙，感觉范围有点大。」

**阶段 2 · 结构化转述与对齐**

> 规范化转述：在城市干线信号协调控制场景下，基于深度强化学习的配时策略相较定周期配时，能否降低车辆平均延误，其收益成立的路网条件与数据前提是什么？

| 要素 | 我的理解 | 来源 |
| --- | --- | --- |
| 研究对象与边界 | 城市道路信号交叉口（单点或干线），不含高速匝道与区域宏观交通流 | 推断 |
| 核心变量 | 自变量：配时策略（深度强化学习 vs 基准）；因变量：平均车辆延误、排队长度 | 推断（原文仅提「拥堵」） |
| 约束与假设 | 需有可获取的流量/排队检测数据，或可用的交通仿真环境 | 推断 |
| 期望产出 | 一个可比较的配时策略 + 量化评估结论 | 推断（由「能不能帮上忙」推得） |
| 需澄清的术语 | 「拥堵」需落到具体指标；「帮上忙」需落到比较基准 | 原文 |

待确认项：

1. 研究场景是单点交叉口、干线协调，还是区域路网？
2. 评价以真实数据、开源数据集，还是交通仿真（如 SUMO）为准？
3. 是否需要与经典配时方法对照，还是仅评估深度学习方法自身？

> 以上对齐是否准确？请确认，或指出需要修正的编号项。确认后我再输出子问题拆解表。

（本轮到此停止，不输出任何子问题。）

**用户回复**：「确认，场景为干线协调，用 SUMO 仿真，需要与定周期配时对照。」

**阶段 4 · 表格化拆解与原因说明**

本次采用**方法链维度**为主线，辅以**约束维度**检验泛化性。

| 序号 | 子问题（规范化表述） | 拆解维度 | 拆解原因 | 前置依赖 |
| --- | --- | --- | --- | --- |
| Q1 | 在干线协调场景下，如何用状态、动作、奖励三元组形式化配时决策，并使奖励与平均车辆延误、排队长度相对齐？ | 方法链（表征） | 原文「拥堵」与「帮上忙」均未被定义；不先固定量化判据，后续所有比较都缺少统一基准。 | 无 |
| Q2 | 在 SUMO 干线路网与给定流量需求下，深度强化学习配时策略相比定周期配时，平均延误与排队长度的降幅是多少？ | 方法链（建模求解） | 这是总问题的核心可检验命题，单列以保证结论有明确的对照组与效应量。 | Q1 |
| Q3 | 上述降幅在流量饱和度、干线长度与转向比例变化时是否保持，失效的临界条件是什么？ | 约束维度 | 仿真结论易过拟合到单一路网配置；不单列边界检验，就无法回答「在什么条件下才帮得上忙」。 | Q2 |
| Q4 | 策略收敛所需训练步数与单步推理时延，是否满足在线配时的实时性约束？ | 方法链（验证） | 工程可用性与效果优劣是两个独立命题，合并会使「有效」的含义含混。 | Q2 |

**拆解逻辑**：原始设想同时混有「要不要用深度学习」「效果如何」「能否落地」三层诉求，按方法链切分可让每层各有一个可独立证伪的出口。

**逻辑结构**：Q1 → Q2 → {Q3, Q4}，先串行后并行；建议先固定 Q1 的指标定义，再执行 Q2 的对照实验。

**边界与未覆盖**：未纳入真实路网数据获取、多智能体区域协调，以及信号配时的安全与法规约束。

## 4. MECE 与质量自检表

| 检查项 | 判定标准 |
| --- | --- |
| 互斥 | 任意两条子问题不能由同一组实验或同一段推导完全回答 |
| 完备 | 全部子问题回答后，规范化总问题不再留有未回答的部分 |
| 原子性 | 每条只含一个待检验命题 |
| 粒度一致 | 各条所需工作量处于同一量级，不出现一条顶三条 |
| 可检验 | 每条都能说出「用什么数据、推导或实验判定它成立」 |
| 原因具体 | 拆解原因指向总问题的某一具体成分，而非「便于研究」 |

不满足任一项时，在阶段 4 的「边界与未覆盖」中说明取舍，不要静默放过。
